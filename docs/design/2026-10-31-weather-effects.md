# 天气效果对照表

后端 `GET /api/app/weather` 返回 WMO 天气代码，App 侧 `WeatherKind` 归成 8 组，
两个小组件各按自己的语言表达。这张表是"改代码前先查这里"的唯一依据。

## 一、8 组天气与 WMO 代码

| 组 | WMO code | 中文 | 云量系数 | 降水 |
|---|---|---|---|---|
| `clear` 晴 | 0, 1 | 晴 / 晴间多云 | 0 | 无 |
| `partly` 多云 | 2 | 多云 | 0.45 | 无 |
| `overcast` 阴 | 3 | 阴 | 0.95 | 无 |
| `fog` 雾 | 45, 48 | 有雾 / 雾凇 | 0.60 | 无 |
| `drizzle` 毛毛雨 | 51, 53, 55, 56, 57 | 毛毛雨系列 | 0.70 | 毛毛雨 |
| `rain` 雨 | 61, 63, 65, 66, 67, 80, 81, 82 | 小/中/大/阵/暴 | 0.85 | 雨 |
| `snow` 雪 | 71, 73, 75, 77, 85, 86 | 小/中/大/阵雪 | 0.80 | 雪 |
| `thunder` 雷 | 95, 96, 99 | 雷阵雨 / 雷暴 | 0.95 | 雨（`isSevere`） |

未知代码 → `nil`，**不兜底成晴**。缺数据就按"没有天气"渲染，不能骗人。

## 二、两个组件各画什么

| 天气 | 每日简报（纸面 + 轨迹） | 天光（天空 + 地平线 + 太阳） |
|---|---|---|
| 晴 | 暖褐底 + 金色中心柔光 α0.30，无粒子 | 不叠加任何东西（现有最好看，不画蛇添足） |
| 多云 | 2 朵云 α0.12（上半部）+ 柔光 α0.22 | 2 朵云 α0.55 |
| 阴 | 3 朵云 α0.16 + 一层 ground 薄纱 α0.10 | 4 朵云 α0.42 互相压住，形成"压顶" |
| 雾 | 轨迹下方一条横向雾带（卡高 18%） | 天空区下 30% 高的一条雾带，上下淡出 |
| 毛毛雨 | 10 条极短竖划（4–5pt）α0.18 | 12 条竖划，只在天空区最低 40pt |
| 雨 | 20 条斜划（12°、8–12pt）α0.22 | 22 条斜划（10°），天顶 → 地平线 |
| 雪 | 14 个 1.5pt 白点 α0.35 | 16 个 1.5–2pt 点，下密上疏（`1−v²`） |
| 雷 | 18 条雨 + 一道三折闪电 α0.5 | 阴天云 + `sky.ground`@0.18 暗纱 + 20 条雨 + 一道闪电 |

**净空带**：简报卡正文上下各留 20pt 不放粒子 —— 雨丝切碎正文比没有效果更糟。

## 三、简报卡的 8 档底色（`Theme.Weather`）

固定色，**不参与换肤**：天气是物理事实，切到樱粉主题不该把雨染成粉色。

| 天气 | 底色（top） | 柔光（glow） |
|---|---|---|
| 晴 | 暖褐黑 | 暖金 |
| 多云 | 深蓝灰 | 银蓝 |
| 阴 | 冷灰 | 灰蓝 |
| 雾 | 灰青 | 青灰 |
| 毛毛雨 | 深青 | 青 |
| 雨 | 深蓝 | 蓝 |
| 雪 | 冷青白 | 冷白 |
| 雷 | 近黑紫 | 紫 |

八档的下沿都收敛到 `sky(.night).ground`（同一块近黑），**只有上半张在变天** ——
这样八种天气放在一起仍像同一套卡片，而不是八张不同设计的卡。

## 四、"能动"的真相（写清楚，免得以后当 bug 修）

WidgetKit 的小组件**没有持续动画**：不能跑 Timer、`withAnimation` 在组件里是死代码。
系统只在 timeline 排好的时间点重绘一次。

所以云的"飘"是这样实现的：

```
云 x = (基线 + 当天进度 × 速度系数) mod 1 × 卡宽
```

- 简报：60 分钟一帧，每帧挪约 0.4% 卡宽，一天走完 35%
- 天光：30 分钟一帧，四朵云速度系数各不相同（0.28 / 0.30 / 0.31 / 0.33），
  避免看起来像"整张图在平移"
- 取模保证不出界

观感是"隔一阵看一眼，它挪了一点"，不是流畅飘动。这是平台限制，不是实现偷懒。
**想要真动画，只能在 App 内的卡片里做**（SwiftUI 可以跑持续动画）。

## 五、刷新预算

| 组件 | 帧数 | 理由 |
|---|---|---|
| 简报 | 60 分钟 × 24 帧 | 简报内容一天只变一次，帧是为了云和天气色 |
| 天光 | 30 分钟 × ~103 帧 | 需要覆盖 7 次天色换档点 + 太阳平滑移动，预排帧不额外消耗刷新预算 |
| 红石 | 1 帧 + `Text(timerInterval:)` | 倒计时由系统自绘，零刷新成本 |

一轮 `getTimeline` 只发 **1 次**天气请求，然后打给这一轮所有帧 —— 天气不会半小时一变，
每帧都拉会把上游打到限流。
